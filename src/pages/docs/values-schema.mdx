# Values Schema

Every HelmForge chart publishes a `values.yaml` file and a matching `values.schema.json` contract. The schema validates
value types, allowed choices, and object structure before Kubernetes resources are rendered. Templates also enforce
cross-field requirements that cannot be expressed safely in JSON Schema alone.

## Find a chart contract

- Use the [chart documentation](/docs/charts) for installation examples, operational guidance, and the complete
  configuration reference.
- Use the [playground](/playground) to build a values file interactively from the published schema.
- Browse the [charts repository](https://github.com/helmforgedev/charts/tree/main/charts) to inspect `values.yaml`,
  `values.schema.json`, templates, and CI scenarios together.

## Inspect a packaged schema

Add the HelmForge repository, download a chart, and inspect the files included in the package:

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm pull helmforge/mysql --untar --untardir ./helmforge-chart
helm show values helmforge/mysql
```

The downloaded JSON Schema is available at `./helmforge-chart/mysql/values.schema.json`. Replace `mysql` with the chart
name you want to inspect.

## Validate custom values

Validate a local values file before installation:

```bash
helm lint --strict ./helmforge-chart/mysql -f values.yaml
helm template my-mysql ./helmforge-chart/mysql -f values.yaml > rendered.yaml
```

Schema validation is the first gate. Also review the chart documentation for required Secrets, persistent storage,
network access, upgrade constraints, and production hardening options.
