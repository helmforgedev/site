# Castopod

Open-source podcast hosting platform. Castopod manages your episodes, generates RSS feeds for distribution to
Apple Podcasts, Spotify, and other directories, tracks anonymous listener analytics, and federates with the
Fediverse via ActivityPub. Metadata lives in MariaDB and uploaded audio and images live on a persistent volume.
The chart applies migrations and creates the superadmin on first start, so the instance never opens with a public
install wizard.

## Key Features

- **RSS feed generation** — automatic, standards-compliant podcast feeds for all directories
- **Built-in analytics** — privacy-respecting listener tracking with hashed IDs
- **Fediverse integration** — ActivityPub support for social interactions and episode sharing
- **Ready on first start** — setup init container runs migrations and creates the superadmin from a Secret
- **Hardened pod** — non-root `www-data`, no privilege escalation, all capabilities dropped except `NET_BIND_SERVICE`
- **Scheduler sidecar** — scheduled publishing, WebSub, and federation tasks run every minute
- **MariaDB backend** — bundled subchart or external database on any port
- **Optional Redis cache** — authenticated Redis subchart as the cache handler
- **Persistent media** — one PVC holds the writable directory and uploaded audio and images
- **S3 backup** — scheduled archive of the data volume to S3-compatible storage
- **Configurable listener** — `castopod.port` changes the real FrankenPHP port
- **Ingress or Gateway API** — Ingress or HTTPRoutes
- **CDN support** — separate media base URL for audio file delivery

## Installation

**HTTPS repository:**

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install castopod helmforge/castopod \
  --set castopod.baseURL=https://podcast.example.com
```

**OCI registry:**

```bash
helm install castopod oci://ghcr.io/helmforgedev/helm/castopod \
  --set castopod.baseURL=https://podcast.example.com
```

`castopod.baseURL` only sets the URL that Castopod embeds in links and feeds. It does not expose the Service: enable
`ingress` or `gatewayAPI` for that hostname (see the Deployment Examples below) before using the public URL.

## Getting Started

Without a base URL, Ingress, or HTTPRoute, the chart uses `http://localhost:8080` and disables HTTPS redirection
for a local check:

```bash
helm install castopod helmforge/castopod
kubectl rollout status deploy/castopod-castopod --timeout=300s
kubectl get secret castopod-castopod-admin -o jsonpath='{.data.admin-password}' | base64 -d; echo
kubectl port-forward svc/castopod-castopod 8080:80
```

Open `http://localhost:8080/cp-auth/login` and log in with `admin@example.com` and the password above.

<Callout type="warning" title="baseURL is required and affects all RSS feeds">
  All episode audio URLs, podcast RSS feed links, and API responses are built using `castopod.baseURL`. If this value is

  Always set the exact public URL including `https://` and without a trailing slash.
</Callout>

### Analytics

| Parameter                     | Type   | Default          | Description                                                                   |
| ----------------------------- | ------ | ---------------- | ----------------------------------------------------------------------------- |
| `analytics.salt`              | string | `""`             | Salt for hashing listener IDs. Generated once (64 chars) and kept on upgrade. |
| `analytics.existingSecret`    | string | `""`             | Existing Kubernetes Secret containing the analytics salt.                     |
| `analytics.existingSecretKey` | string | `analytics-salt` | Key inside the existing secret holding the salt value.                        |

<Callout type="info" title="Persist the analytics salt for consistent reporting">
  The analytics salt is used to hash listener IP addresses into anonymous IDs. If the salt changes, historical listener
  data becomes inconsistent — the same listener appears as multiple distinct users across time periods. The chart keeps
  a generated salt across upgrades; set `analytics.existingSecret` to manage it outside the release.
</Callout>

### Persistence

One PVC holds two paths: the volume root is mounted at `/var/www/html/writable` (cache, sessions, logs, temporary
files) and the `public-media` subPath at `/var/www/html/public/media` (uploaded audio, artwork, and site images).

| Parameter                   | Type    | Default         | Description                                             |
| --------------------------- | ------- | --------------- | ------------------------------------------------------- |
| `persistence.enabled`       | boolean | `true`          | Enable a PVC for writable files and uploaded media.     |
| `persistence.size`          | string  | `10Gi`          | PVC size. Increase based on expected audio file volume. |
| `persistence.storageClass`  | string  | `""`            | StorageClass for the PVC.                               |
| `persistence.accessMode`    | string  | `ReadWriteOnce` | PVC access mode.                                        |
| `persistence.existingClaim` | string  | `""`            | Use an existing PVC instead of creating one.            |
| `persistence.annotations`   | object  | `{}`            | Annotations for the PVC.                                |

### Backup

<Callout type="warning" title="S3 backup covers the data volume only — not MariaDB">
  The S3 backup CronJob archives the Castopod data volume (writable files and uploaded audio and images). It does
  **not** back up the MariaDB database, which contains episode metadata, podcast definitions, user accounts, and

</Callout>

| ------------------------------ | ------- | ------------------------------------------------- | -------------------------------------------------------------- |
| `resources`                    | object  | `{}`                                              | CPU and memory requests and limits for the Castopod container. |

<Callout type="info" title="Why the chart does not run the upstream s6-overlay supervisor">
  The image's `/init` supervisor depends on a setuid helper that fails without privilege escalation. The chart runs
  FrankenPHP and the scheduler as separate containers and runs the upstream bootstrap in the setup init container, so
  the pod can stay non-root with no privilege escalation. The FrankenPHP binary carries the `NET_BIND_SERVICE` file
  capability, which therefore stays in the bounding set.
</Callout>

## Common Issues

<Callout type="danger" title="Episodes not playing in podcast apps after URL change">
  If you change `castopod.baseURL` after publishing episodes, all RSS feed URLs will change and existing subscribers may
  lose access until their podcast app refreshes the feed. Plan your URL carefully before the first publish. If you must
  change it, use a 301 redirect from the old URL to the new one.
</Callout>

<Callout type="tip" title="Log in with the superadmin email">
  The setup init container creates the superadmin from `castopod.admin.*` once, when no owner exists. Log in at
  `/cp-auth/login` with the email and the password from `<release>-castopod-admin`. To use the `/cp-install` wizard
  instead, set `castopod.admin.create=false` and complete it before exposing the instance: the first visitor becomes
  the owner.
</Callout>

<Callout type="info" title="Pod stuck in Init:0/1">
  The setup init container waits up to `setup.databaseWaitTimeoutSeconds` for MariaDB. Read
  `kubectl logs deploy/<release>-castopod -c setup` to see whether the database is unreachable or rejects the
  credentials.
</Callout>
