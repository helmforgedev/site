# Discourse

Deploy [Discourse](https://www.discourse.org/) with the official upstream ESR
image, PostgreSQL with pgvector, Redis, and persistent `/shared` storage.

<Callout type="warning" title="Experimental and not upstream-supported for production">
  Discourse classifies its official container image and Kubernetes deployment path as unsupported for production.
  HelmForge validates this beta chart, but does not convert that upstream limitation into a production support claim.
</Callout>

## Key Features

- Official multi-architecture image pinned by immutable digest
- Enforced singleton Deployment with `Recreate` updates
- Bundled PostgreSQL 18 with pgvector and bundled Redis
- External PostgreSQL and Redis with existing Secret support
- Persistent `/shared` uploads, backups, logs, and runtime state
- Ingress, Gateway API, dual-stack Service, NetworkPolicy, and External Secrets
- Upstream `/srv/status` startup, readiness, and liveness probes

## Installation

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install discourse helmforge/discourse --wait --timeout 20m
```

OCI installation:

```bash
helm install discourse oci://ghcr.io/helmforgedev/helm/discourse --wait --timeout 20m
```

The expanded upstream image is approximately 5.2 GB. A cold node and the first
migration/asset compilation can take many minutes.

```yaml
postgresql:
  enabled: false
database:
  mode: external
  external:
    host: postgresql.database.svc.cluster.local
    port: 5432
    name: discourse
    username: discourse
    existingSecret: discourse-database
    existingSecretPasswordKey: database-password

redis:
  enabled: false
  external:
    host: redis.cache.svc.cluster.local
    port: 6379
    existingSecret: discourse-redis
    existingSecretPasswordKey: redis-password
```

External PostgreSQL must provide `pg_trgm`, `unaccent`, and `vector`, and the
application user must be allowed to run migrations.

## Security and Operations

The root and writable-filesystem exceptions are required by the official image.
Privilege escalation is disabled, capabilities are minimized, and API token
mounting is disabled. Back up PostgreSQL and `/shared` together before upgrades.
Do not increase `replicaCount` or use rolling updates.

```bash
kubectl rollout status deployment/RELEASE-discourse -n NAMESPACE --timeout=20m
kubectl logs deployment/RELEASE-discourse -n NAMESPACE -c discourse --tail=300
kubectl get events -n NAMESPACE --sort-by=.lastTimestamp
```

## Known Limitations

- No upstream production support for the container/Kubernetes path
- Single replica only, without application high availability
- Root and writable root filesystem required
- Plugins require a custom image
- No chart-managed Prometheus endpoint or backup Job
