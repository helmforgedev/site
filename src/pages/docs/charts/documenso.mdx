# Documenso

[Documenso](https://documenso.com) is an open-source electronic-signature
platform. The HelmForge chart deploys the official Documenso v2.21.0 image with
a maintained PostgreSQL dependency, optional BullMQ/Redis, immutable identity
keys, signing-certificate support, and production-oriented Kubernetes defaults.

The chart is beta. The official entrypoint applies Prisma migrations during
startup, and the chart deliberately preserves that supported behavior.

## What this chart provides

- immutable official Linux amd64/arm64 image pinned by manifest digest;
- HelmForge PostgreSQL 2.1.1 and optional HelmForge Redis 3.1.0 subcharts;
- external PostgreSQL, Redis, SMTP, S3, signing, and Gotenberg Secret contracts;
- local, BullMQ, and Inngest background-job modes;
- native External Secrets Operator resources;
- Ingress and Gateway API HTTPRoute exposure;
- non-root UID/GID 1001, read-only root filesystem, dropped capabilities,
  runtime-default seccomp, and no mounted API token;
- product-aware NetworkPolicy, dual-stack Service, PodDisruptionBudget, optional
  autoscaling, and scale-out invariants;
- application health and certificate-status probes.

The application has no chart-owned PVC. Documents live in PostgreSQL by default
or in configured S3-compatible object storage.

## Install

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install documenso helmforge/documenso \
  --version 1.0.0 \
  --namespace documenso \
  --create-namespace
```

The default is a basic single-replica installation with persistent PostgreSQL
and database-backed local jobs. Configure a PKCS#12 signing certificate before
using document signatures. Keep public registration protected until
administration and email delivery have been verified.

## Image provenance and health

The chart pins the official v2.21.0 multi-platform manifest:

```text
ghcr.io/documenso/documenso@sha256:d9985f66c19c59128f64b1439f057683da0110deb0e518655b97f06e3141f173
```

Startup and readiness call `/api/health`. TCP liveness deliberately remains
independent of PostgreSQL so a database outage does not trigger a restart
storm. `/api/certificate-status` provides signing diagnostics.

## Protect application identity

Documenso requires stable NextAuth and encryption keys. The default Secret is
generated once and retained with Helm cluster lookup. GitOps deployments should
supply an existing Secret because offline renderers cannot perform that lookup:

```yaml
documenso:
  existingSecret: documenso-identity
  nextAuthSecretKey: nextauth-secret
  encryptionKeyKey: encryption-key
  encryptionSecondaryKeyKey: encryption-secondary-key
```

Back up this Secret. Rotating encryption keys without an application migration
can make stored values unreadable.

## Configure production signing and email

Store a PKCS#12 certificate and passphrase in a Secret:

```yaml
certificate:
  enabled: true
  existingSecret: documenso-signing
  fileKey: signing-certificate.p12
  passphraseKey: passphrase

smtp:
  enabled: true
  host: smtp.example.com
  port: 587
  existingSecret: documenso-smtp
```

The certificate mounts read-only. SMTP username and password are read from the
configured Secret keys and never copied into a ConfigMap.

## Scale with BullMQ and S3

Multiple replicas require a shared job queue and document store. The chart
rejects unsafe combinations:

```yaml
replicaCount: 2

documenso:
  jobsProvider: bullmq

redis:
  enabled: true

objectStorage:
  provider: s3
  s3:
    bucket: signed-documents
    region: us-east-1
    endpoint: https://s3.example.com
    forcePathStyle: true
    existingSecret: documenso-s3
```

For production, managed PostgreSQL, Redis, and object storage provide stronger
availability and recovery guarantees than in-cluster standalone dependencies.

## Use external PostgreSQL and Redis

```yaml
postgresql:
  enabled: false
database:
  external:
    enabled: true
    host: postgres.database.svc
    port: 5432
    existingSecret: documenso-database
    urlKey: database-url
    directUrlEnabled: true
    directUrlKey: direct-database-url
    networkPolicyPeers:
      - namespaceSelector:
          matchLabels:
            kubernetes.io/metadata.name: database

documenso:
  jobsProvider: bullmq
redis:
  enabled: false
  external:
    enabled: true
    host: redis.cache.svc
    port: 6379
    existingSecret: documenso-redis
    networkPolicyPeers:
      - namespaceSelector:
          matchLabels:
            kubernetes.io/metadata.name: cache
```

The database Secret contains complete URL-encoded connection URLs. The direct
URL lets Prisma migrations bypass a pooler. Host and port remain separate for
dependency waiting and NetworkPolicy.

## External Secrets

The canonical `items[]` contract can materialize every Secret used by the
chart:

```yaml
externalSecrets:
  enabled: true
  refreshInterval: 1h
  items:
    - fullnameOverride: documenso-identity
      spec:
        secretStoreRef:
          name: production
          kind: ClusterSecretStore
        target:
          creationPolicy: Owner
        dataFrom:
          - extract:
              key: documenso/identity

documenso:
  existingSecret: documenso-identity
```

Each item accepts a complete native ExternalSecret `spec`. A default target
name and refresh interval are injected when omitted.

## Expose the application

Ingress and Gateway API are opt-in and mutually exclusive. Set
`documenso.publicUrl` explicitly in production:

```yaml
documenso:
  publicUrl: https://sign.example.com

gatewayAPI:
  enabled: true
  httpRoutes:
    - name: web
      parentRefs:
        - name: public
          namespace: gateway-system
      hostnames:
        - sign.example.com
```

NetworkPolicy allows namespace-local HTTP ingress, DNS, declared state
services, public HTTP/HTTPS, and the configured public SMTP port while excluding
private address ranges. Add explicit egress rules for private SMTP, S3,
Gotenberg, OAuth, or webhook destinations. Add an Ingress or Gateway controller
from another namespace to `networkPolicy.ingressFrom`.

## Backup and restore

Protect PostgreSQL, the S3 bucket when enabled, application identity, signing
certificate, and integration Secrets as one recovery set. Preserve Redis too
when in-flight BullMQ jobs must survive.

Before upgrades, restore the backup into an isolated namespace with the same
application image, then verify health, login, document access, and signing. The
upstream entrypoint runs Prisma migrations, so an image-only rollback cannot
reverse database schema changes.

## Uninstall

```bash
helm uninstall documenso --namespace documenso
```

Confirm that PostgreSQL PVCs and any external object storage are backed up
before uninstalling.
