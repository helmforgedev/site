# BookLore

Deploy [BookLore](https://github.com/booklore-app/booklore) on Kubernetes using the official `ghcr.io/booklore-app/booklore` container image.
A self-hosted eBook library management application with metadata fetching, OPDS support,
and a modern web-based reader for managing your personal digital book collection.

<Callout type="danger" title="Back up MariaDB and every enabled storage domain">
  BookLore stores relational state in MariaDB and uses separate filesystem domains: `/app/data` for application data,
  settings, and caches; `/books` for the physical library; and optional `/bookdrop` for imports. A recoverable snapshot
  must keep MariaDB and these volumes consistent.
</Callout>

## Key Features

- **MariaDB bundled** -- HelmForge MariaDB subchart handles the database automatically
- **External database** -- connect to an existing MariaDB/MySQL instance instead
- **Triple PVC architecture** -- `/app/data` (metadata), `/books` (library files), `/bookdrop` (imports)
- **OIDC guardrail** -- force-disable upstream OIDC while it is configured through the BookLore interface
- **Remote/proxy auth** -- header-based authentication for reverse proxy setups
- **NetworkPolicy** -- egress constrained to kube-system (DNS) and MariaDB only
- **Gateway API** -- optional HTTPRoute support for clusters using Gateway API
- **External Secrets** -- optional ExternalSecret items for secrets management
- **HPA guardrails** -- validation prevents multi-replica scaling with ReadWriteOnce storage

## Architecture

The Service targets the Deployment's named `http` port. `app.port` configures
the actual `BOOKLORE_PORT` listener and all health probes; `service.port`
remains an independent Kubernetes-facing port. BookLore connects to the
bundled or external MariaDB service and mounts separate data, books, and
optional BookDrop volumes.

The official health endpoint is `/api/v1/healthcheck`. The default
`Recreate` strategy prevents overlapping mounts during upgrades that use
`ReadWriteOnce` storage.

## Installation

**HTTPS repository:**

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install booklore helmforge/booklore -f values.yaml
```

**OCI registry:**

```bash
helm install booklore oci://ghcr.io/helmforgedev/helm/booklore -f values.yaml
```

## Configuration Reference

### Application Settings

| Parameter            | Description                         | Default |
| -------------------- | ----------------------------------- | ------- |
| `app.port`           | HTTP port inside the container      | `6060`  |
| `app.rootLogLevel`   | Root log level                      | `INFO`  |
| `app.logLevel`       | BookLore-specific log level         | `INFO`  |
| `app.allowedOrigins` | CORS allowed origins                | `"*"`   |
| `app.diskType`       | `LOCAL` or read-safe `NETWORK` mode | `LOCAL` |
| `app.env`            | Additional environment variables    | `[]`    |
| `app.envFrom`        | Additional envFrom sources          | `[]`    |

### Image Configuration

| Parameter          | Description                | Default                         |
| ------------------ | -------------------------- | ------------------------------- |
| `image.repository` | Container image repository | `ghcr.io/booklore-app/booklore` |
| `image.tag`        | Image tag (pinned)         | `v2.3.1`                        |
| `image.pullPolicy` | Image pull policy          | `IfNotPresent`                  |

| -------------------------------- | ------------------------------------- | ------------------- |

| Parameter                           | Description                                   | Default |
| ----------------------------------- | --------------------------------------------- | ------- |
| `monitoring.serviceMonitor.enabled` | Create ServiceMonitor for Prometheus          | `false` |
| `monitoring.serviceMonitor.path`    | Metrics endpoint path (required when enabled) | `""`    |

| `autoscaling.maxReplicas`           | Maximum replicas                              | `3`     |

<Callout type="warning" title="BookLore v2.3.1 does not expose Prometheus metrics">
  The current upstream image does not include a Prometheus metrics endpoint. Enable `monitoring.serviceMonitor` only if
  you build a custom image with `micrometer-registry-prometheus` or when upstream adds native support. You must set
  `monitoring.serviceMonitor.path` to a real Prometheus exposition endpoint.
</Callout>

<Callout type="warning" title="HPA requires ReadWriteMany storage">
  Setting `replicaCount > 1` or autoscaling with `maxReplicas > 1` requires every enabled persistence volume to
  declare `ReadWriteMany`. The chart rejects unsafe data, books, and BookDrop combinations before installation.
</Callout>

## Security and production boundaries

- Service-account token mounting is disabled by default.
- Database credentials can come from an existing Secret or ExternalSecret;
  inline passwords remain visible in Helm release state.
- Restrict `app.allowedOrigins` to the public HTTPS origin and allow required
  metadata-provider egress when enabling NetworkPolicy restrictions.
- `app.diskType=NETWORK` disables file writes and reorganization for
  network-attached book storage; it does not make every network filesystem
  safe or supported.
- The stock pinned image has no Prometheus endpoint, so ServiceMonitor remains
  disabled unless an operator supplies a compatible image and path.

## Troubleshooting

- For slow startup, inspect Flyway and MariaDB logs before restarting the pod.
- For probe failures, verify `BOOKLORE_PORT` matches `app.port` and request
  `/api/v1/healthcheck` inside the container.
- For missing books, verify the `/books` PVC and `app.diskType` contract.
- For database failures, verify the JDBC endpoint, username, and Secret key
  refer to the same MariaDB instance.
