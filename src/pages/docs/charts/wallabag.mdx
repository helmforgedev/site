# Wallabag

Self-hosted read-it-later application. Wallabag saves articles from the web by extracting their full text and
storing them in your own PostgreSQL database. Read your saved articles offline across any device, organize them
with tags, annotations, and reading lists, and share them with configurable access controls.

## Key Features

- **Full-text extraction** — saves the complete article content, not just a link
- **Multi-device access** — web UI, mobile apps, browser extensions, and e-reader exports
- **Tag and annotation system** — organize articles with tags, highlights, and notes
- **Working first install** — a setup init container installs the schema on first start and runs Doctrine migrations
  on every upgrade
- **Initial super-admin from a Secret** — configurable username and email with a generated or supplied password
- **PostgreSQL backend** — bundled subchart or external database
- **Optional Redis** — subchart or external Redis for the asynchronous import queue
- **Persistent storage** — PVC-backed data directory for downloaded article images
- **S3 backup** — scheduled `pg_dump` of the Wallabag database to S3-compatible storage
- **Ingress and Gateway API** — Ingress with TLS or Gateway API HTTPRoutes
- **Hardened defaults** — no privilege escalation, minimal capabilities, `RuntimeDefault` seccomp, no ServiceAccount
  token

## Installation

**HTTPS repository:**

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install wallabag helmforge/wallabag
```

**OCI registry:**

```bash
helm install wallabag oci://ghcr.io/helmforgedev/helm/wallabag
```

## Getting Started

The first pod start installs the schema and creates the initial super-admin. Read its password and open the UI:

```bash
kubectl rollout status deploy/wallabag-wallabag --timeout=300s
kubectl get secret wallabag-wallabag-admin -o jsonpath='{.data.admin-password}' | base64 -d; echo
kubectl port-forward svc/wallabag-wallabag 8080:80
```

Log in at `http://localhost:8080/` as `wallabag` (or `wallabag.admin.username`). Resource names follow
`<release>-wallabag`.

### Database Setup

| Parameter                          | Type    | Default | Description                                                         |
| ---------------------------------- | ------- | ------- | ------------------------------------------------------------------- |

<Callout type="warning" title="Change domainName before deploying">
  The default `wallabag.domainName` is `https://wallabag.example.com`. Wallabag uses this value to generate internal
  links for article sharing, e-reader exports, and API responses. Deploy with your actual public URL or internal links
  will be broken.
</Callout>

<Callout type="warning" title="Use existing Secrets with GitOps">
  When `wallabag.secret` and `wallabag.admin.password` are empty, the chart generates them once and reads them back from
  the cluster on `helm upgrade`. Tools that render without cluster access, such as Argo CD or `helm template`, generate
  new values on every render. Set `wallabag.existingSecret` and `wallabag.admin.existingSecret` in that case.
</Callout>

<Callout type="info" title="Initial super-admin and registration">
  The upstream installer always creates `wallabag/wallabag`. The chart replaces it on the first install with
  `wallabag.admin.username`, `wallabag.admin.email`, and the password from the admin Secret. Later password changes go
  through the Wallabag UI. `wallabag.registration: false` keeps public sign-ups disabled.
</Callout>

<Callout type="info" title="Why the container starts as root">
  The upstream image renders its configuration and starts nginx as root, then runs PHP-FPM as `nobody`. `runAsNonRoot`
  and a read-only root filesystem are therefore not supported. The defaults drop every capability except `CHOWN`,
  `DAC_OVERRIDE`, `FOWNER`, `SETGID`, `SETUID`, and `NET_BIND_SERVICE`.
</Callout>

## Common Issues

<Callout type="danger" title="Articles not loading — domainName mismatch">
  If articles fail to load or share links are broken, verify that `wallabag.domainName` matches the exact public URL you
  are using to access Wallabag, including the `https://` prefix and without a trailing slash. A mismatch causes Wallabag
  to generate internal links pointing to the wrong host.
</Callout>

<Callout type="danger" title="HTTP 500 on every page">
  Wallabag returns HTTP 500 when its schema is missing. Check `kubectl logs deploy/<release>-wallabag -c setup` and
  confirm that `setup.enabled` is `true` and PostgreSQL is reachable with the configured credentials.
</Callout>

<Callout type="info" title="Restoring a backup">
  The setup container creates the schema on first start. Restore a `pg_dump` archive into an empty `public` schema while
  Wallabag is scaled to zero; on the next start the setup container only applies newer migrations.
</Callout>
