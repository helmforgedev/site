# Transmute

Deploy [Transmute](https://transmute.sh/), a self-hosted file conversion
platform, with the official pinned image and a production-safe single-writer
topology. Upstream source and release history are available in the
[Transmute repository](https://github.com/transmute-app/transmute).

## Features

- Persistent users, jobs, uploads and outputs under `/app/data`.
- Stable JWT signing key across pod restarts and chart upgrades.
- Native OIDC with public and optional cluster-internal issuer URLs.
- Ingress, Gateway API v1 HTTPRoute and IPv4/IPv6 dual-stack Service support.
- External Secrets Operator resources using complete `items[].spec` definitions.
- Non-root execution, read-only root filesystem, no Linux capabilities and no
  mounted ServiceAccount token.
- Helm connection test using the upstream readiness endpoint.

## Install

### Helm repository

```bash
helm repo add helmforge https://repo.helmforge.dev
helm repo update
helm install transmute helmforge/transmute \
  --namespace transmute --create-namespace
```

### OCI registry

```bash
helm install transmute oci://ghcr.io/helmforgedev/helm/transmute \
  --namespace transmute --create-namespace
```

Before enabling Ingress or Gateway API, port-forward the Service privately, open
`http://127.0.0.1:8080`, and register the first account. On a new volume, that
first account becomes administrator.

```bash
kubectl port-forward service/transmute-transmute 8080:8080 --namespace transmute
```

## Single-writer design

Transmute stores its database and conversion state locally. For data integrity,
the chart requires `replicaCount: 1`, requires persistence and uses a `Recreate`
Deployment strategy. Horizontal replicas are not supported by upstream's SQLite
architecture. `config.dataDir` must equal `persistence.mountPath` so application
state cannot be redirected to ephemeral storage.

## OIDC

Register this callback URI with Keycloak, Authentik, Authelia or another
OpenID Connect provider:

```text
https://transmute.example.com/api/oidc/callback
```

```yaml
config:
  appUrl: https://transmute.example.com

oidc:
  enabled: true
  issuerUrl: https://id.example.com/realms/main
  internalUrl: http://keycloak.identity.svc/realms/main
  clientId: transmute
  clientSecret: replace-me
  displayName: Company SSO
  usernameClaim: preferred_username
  autoCreateUsers: true
  autoLaunch: false
```

`internalUrl` is optional and is useful when pods cannot reach the public
issuer. Transmute derives the callback from `config.appUrl` and requests the
fixed scopes `openid email profile`.

## External Secrets

Use `auth.existingSecret` to point the Deployment to the Secret produced by ESO:

```yaml
auth:
  existingSecret: transmute-auth

externalSecrets:
  enabled: true
  items:
    - fullnameOverride: transmute-auth
      spec:
        secretStoreRef:
          name: platform-secrets
          kind: ClusterSecretStore
        target:
          name: transmute-auth
          creationPolicy: Owner
        data:
          - secretKey: AUTH_SECRET_KEY
            remoteRef:
              key: applications/transmute
              property: auth-secret-key
          - secretKey: OIDC_CLIENT_SECRET
            remoteRef:
              key: applications/transmute
              property: oidc-client-secret
```

## Gateway API

The Gateway API controller and parent Gateway must already exist. A route rule
without `backendRefs` targets the chart Service automatically. Gateway API and
Ingress may be enabled together.

```yaml
gatewayAPI:
  enabled: true
  httpRoutes:
    - name: public
      parentRefs:
        - name: shared-gateway
          namespace: gateway-system
          sectionName: https
      hostnames:
        - transmute.example.com
```

See the [Gateway API documentation](https://gateway-api.sigs.k8s.io/) for
controller and Gateway setup.

## Dual-stack networking

Leave the Service IP family values unset to inherit the cluster default, or
request dual-stack without forcing an unavailable address family:

```yaml
service:
  ipFamilyPolicy: PreferDualStack
```

Explicit `ipFamilies: [IPv4, IPv6]` is intended for clusters configured for
[IPv4/IPv6 dual-stack](https://kubernetes.io/docs/concepts/services-networking/dual-stack/).

## Backup

All durable data is stored on the single PVC. Quiesce application writes and use
a CSI snapshot or file-level volume backup. Back up the authentication Secret as
well. The chart does not provide an application-aware online backup job.

## Upgrade to chart v2

Version 2 is a breaking correction of the chart's public contract. Before
upgrading:

- replace `config.queueConcurrency` with conversion and compression worker
  concurrency values;
- replace `config.jobTimeout` with `config.conversionJobStaleAfterMinutes`;
- replace `auth.enabled` with `config.allowUnauthenticated`;
- remove `config.storageDir`, `auth.allowRegistration` and `auth.initialAdmin`;
- replace `oidc.providerUrl` with `oidc.issuerUrl`;
- set `config.appUrl` instead of `oidc.redirectUri`;
- replace `oidc.autoRegister` with `oidc.autoCreateUsers`;
- migrate the legacy ESO fields to `externalSecrets.items[].spec`;
- ensure the authentication Secret uses `AUTH_SECRET_KEY`;
- keep one replica and persistent storage enabled.

The old initial administrator, registration, redirect URI, OIDC scope and local
authentication switches did not correspond to upstream Transmute settings and
have been removed.
